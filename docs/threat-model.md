# Threat model — first vertical slice

Scope: identity, verification, profiles, directory, connections, blocks, admin actions.
Assets: account access; verified-affiliation status; profile data (employer, location, history);
the social graph; admin authority; audit trail.

| #   | Threat                                           | Attacker / entry point                     | Impact                                         | Mitigation (implemented unless marked)                                                                                                                                                                                            | Residual risk                                                                      | Test                                                                                                      |
| --- | ------------------------------------------------ | ------------------------------------------ | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| T1  | Impersonate a student/professor to gain trust    | Outsider registering with a personal email | Fake "verified" members contacting students    | Auto-verification only when the mailbox domain is mapped to the **claimed** role; everything else goes to admin review; verified status is derived from the case, never client-writable                                           | Department/year are self-declared; admin judgment errors                           | `verification.test.ts` (student domain cannot verify faculty/alumni; forged `verificationState` rejected) |
| T2  | Collusive / fake peer endorsements               | Rings of fake accounts                     | Fraudulent verification                        | Peer attestation **not built**; only email domain and admin review count as evidence                                                                                                                                              | —                                                                                  | n/a (designed: attestations as supplementary evidence only, ADR-0004)                                     |
| T3  | Broken object-level authorization                | Member changing ids in requests            | Accept others' requests, see hidden profiles   | Participant checks in service layer; non-participants get 404; shared SQL visibility policy                                                                                                                                       | New endpoints that skip the policy                                                 | `relationships.test.ts`, `directory.test.ts`                                                              |
| T4  | Privilege escalation to admin                    | Any member                                 | Approve own/fake verification, suspend others  | Admin role only via CLI (`grant-admin`), never via API; strict schemas reject extra fields; admins cannot decide their own case or change their own status                                                                        | Admin account takeover (password only) — **MFA planned**                           | `verification.test.ts`, `identity.test.ts`                                                                |
| T5  | Blocked/suspended/revoked member still reachable | Harasser                                   | Unwanted contact                               | Visibility predicate excludes blocked (both directions), suspended, unverified; block cancels pending requests and removes connection; suspension revokes sessions and pending requests; accept re-checks counterpart eligibility | Future features must reuse the predicate                                           | `directory.test.ts`, `relationships.test.ts`                                                              |
| T6  | Account enumeration                              | Scraper / attacker                         | Learn who is a member                          | Register always 202 (existing owner gets an email); identical login error for unknown email vs wrong password; dummy argon2 verify equalizes timing; hidden profiles 404                                                          | Timing differences not measured                                                    | `identity.test.ts`                                                                                        |
| T7  | Credential stuffing / brute force                | Botnet                                     | Account takeover                               | argon2id; per-IP rate limit on auth endpoints                                                                                                                                                                                     | Distributed attacks bypass per-IP limits; no lockout/MFA yet                       | `identity.test.ts` (429)                                                                                  |
| T8  | Directory scraping                               | Verified member or stolen session          | Bulk export of alumni data                     | Verified-member gate; per-IP rate limit on search; page size ≤ 50                                                                                                                                                                 | A patient scraper within limits; **per-account quotas and anomaly alerts planned** | rate limit covered for auth only                                                                          |
| T9  | CSRF                                             | Malicious site                             | Actions as the victim                          | `SameSite=Lax` HttpOnly cookie + mandatory custom header on non-GET (forces CORS preflight; no CORS allowed)                                                                                                                      | —                                                                                  | `identity.test.ts`                                                                                        |
| T10 | Session theft                                    | XSS, network                               | Account takeover                               | HttpOnly cookie; `Secure` in HTTPS deployments; tokens stored only as SHA-256; React escapes output; no `dangerouslySetInnerHTML`                                                                                                 | No CSP header yet (**planned with deployment**)                                    | —                                                                                                         |
| T11 | SQL injection                                    | Any input                                  | Data exposure                                  | All values parameterized; LIKE wildcards escaped; dynamic SQL only from server-defined fragments                                                                                                                                  | —                                                                                  | `directory.test.ts` (`%` literal)                                                                         |
| T12 | Verification token replay                        | Mail interception                          | Verify someone else's address                  | 256-bit single-use tokens, hashed, 24 h expiry, atomic `UPDATE … WHERE used_at IS NULL`                                                                                                                                           | Mail transport security                                                            | `identity.test.ts`                                                                                        |
| T13 | Race conditions create duplicate effects         | Concurrent clients                         | Duplicate connections; contradictory decisions | Advisory pair lock + partial unique index + canonical pair PK; `FOR UPDATE` on verification cases; conditional updates                                                                                                            | —                                                                                  | Concurrency tests (verified to fail without the lock)                                                     |
| T14 | Sensitive data in logs                           | Operator / log leak                        | Token or cookie leak                           | Cookie/authorization headers redacted; dev mailer logs subject only                                                                                                                                                               | Production log pipeline not yet designed                                           | —                                                                                                         |
| T15 | Dev mailbox exposed in production                | Anyone                                     | Read verification links                        | Route registered only when `DEV_MAILBOX=true`; config refuses it in production; server refuses to start in production without a real mailer                                                                                       | —                                                                                  | config code path                                                                                          |

Not yet covered (next slices): messaging abuse and spam, reports and moderation abuse, attachment
handling, account deletion/erasure, admin MFA, CSP/security headers, dependency scanning in CI.
